### Décisions prises et notes de maintenance

- **EPUB (annexe 7.1)** : le propriétaire confirme que le téléchargement direct depuis le dépôt GitHub public est acceptable. Aucun transfert vers un stockage privé, renouvellement de secret ou nettoyage d’historique n’est prévu ; le livre est traité comme public.
- **Budget JavaScript** : `gzip` mesure la taille transférable des scripts, pas les images. Les navigateurs modernes utilisent les scripts modernes : **149,03 Ko sur une cible de 150 Ko**, donc cible atteinte avec **0,97 Ko de marge**. Le fichier `nomodule` de **38,70 Ko** est la voie de compatibilité pour les anciens navigateurs ; les navigateurs qui comprennent `type="module"` ignorent les scripts `nomodule` ([MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/script#module_fallback)). Ne pas additionner les deux comme si un visiteur recevait les deux voies. Après la maquette, viser idéalement environ 140 Ko pour retrouver 10 Ko de marge, sans en faire un blocage actuel.
- **Tailwind 4** : migration non requise pour corriger les vulnérabilités détectées, et elle ne supprime pas la dépendance `braces` encore tirée par le greffon ESLint de Next. Tailwind 4 réclame Firefox 128+, alors que le support Next 16.4.2 retenu ici inclut Firefox 111+ ; migrer réduirait donc la compatibilité. Le parseur est mis à jour par une surcharge ciblée et Tailwind reste en 3.4.19. Le correctif forcé qui proposait `eslint-config-next@14.2.35` aurait aussi désaligné ESLint avec Next 16 ; il n’a pas été appliqué.
- **`braces`** : l’avis [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) concerne `braces <= 3.0.3` et ne publie pas de version corrigée. Un backport local `3.0.4` dérivé du [PR amont #72](https://github.com/micromatch/braces/pull/72) limite la profondeur à 100 et est couvert par des tests. Le retirer dès qu’un correctif officiel compatible est publié ; provenance et procédure sont dans `vendor/braces/SECURITY_PATCH.md`.
- **Avertissement npm** : `glob@10.5.0` est encore signalé comme déprécié via Tailwind/Sucrase. Il n’est pas signalé par `npm audit` comme vulnérable ; garder ce point séparé des neuf entrées d’audit initiales, aujourd’hui résolues.
- Aucun blocage technique local restant pour compiler ou exécuter les vérifications listées. Les changements restent locaux sur `projet-details`, sans commit, push ni déploiement.

## 0. Synthèse

### 0.1 État général

Le socle est sain : génération statique (`force-static`, `dynamicParams = false`), validation des
contenus en `predev`/`prebuild`, en-têtes de sécurité, analytics Umami limitées à la production,
TypeScript strict sans erreur et ESLint sans erreur (1 avertissement sur `next-intl.config.mjs`).
Les pages projets récentes (`components/projects/`) sont nettement plus abouties que la page
d'accueil : gestion du mouvement réduit, piège de focus dans les dialogues, apparition progressive
qui laisse le contenu visible sans JavaScript.

Les problèmes viennent surtout de **la coexistence de trois générations de code** :

1. la page d'accueil d'origine (`Header`, `Skills`, `Timeline`, `FAQ`, `Footer`) : entièrement
   client, AOS, largeurs fixes, styles gris `rounded-xl` ;
2. le carrousel `Projects3` et le catalogue de projets : framer-motion, styles `rounded-full`
   noir/blanc, données importées côté client ;
3. les études de cas et le blog : Server Components, CSS Modules, navigation et bascule de thème
   propres à chaque section.

Résultat : un JavaScript lourd sur l'accueil, un hero masqué jusqu'à l'hydratation, six études de
cas sur sept invisibles pour les robots depuis l'accueil, et trois « chartes » visuelles
différentes.

| Priorité | Effort | Dépend de |

**Constat**

- **Quatre mécanismes d'animation** :

### U2 — Revoir l'UX du carrousel des projets phares

| Priorité | Effort | Dépend de |
| -------- | ------ | --------- |
| P1       | M      | P3        |

**Constat**

- **Autoplay trop rapide** : 4 s par diapositive (`Projects3.tsx:27`) alors que chaque diapositive
  contient un titre, des badges et une description de **51 à 64 mots** (`carouselDescription`),
  soit 13 à 16 s de lecture. Le contenu change avant d'avoir été lu.
- **Pas de contrôle de pause** : WCAG 2.2.2 demande de pouvoir mettre en pause un contenu qui
  défile automatiquement. Seul le survol à la souris met en pause
  (`Projects3.tsx:378-379`) ; ni le focus clavier, ni le toucher, ni un bouton.
- **Glisser sur tout le panneau** (`drag="x"`, `Projects3.tsx:400-410`) : sur mobile il entre en
  concurrence avec le défilement vertical et la sélection de texte, et un glissement peut
  déclencher un lien.
- **Contrôles bloqués pendant la transition** : `disabled={isAnimating}` et `cursor-wait`
  (`Projects3.tsx:427,454-455`) donnent une impression de lenteur ; on ne peut pas enchaîner deux
  clics.
- **Hauteur fixe** `min-h-[39rem] md:min-h-[33rem]` (`Projects3.tsx:382`) : espace vide pour les
  textes courts, débordement possible pour les longs ou à forte taille de police.
- **Sémantique** : un `role="progressbar"` dans un `role="tab"` ; les onglets n'ont pas de
  `aria-controls` vers un `role="tabpanel"`.

**Mise en œuvre**

1. **Autoplay** : désactivé par défaut, ou 8 s minimum, démarré uniquement quand la section est
   visible (`IntersectionObserver`) ; pause sur survol, `focus-within`, `pointerdown` et onglet
   masqué ; arrêt définitif après une interaction manuelle.
2. **Bouton pause/lecture** visible à côté des points, `aria-pressed`, libellé traduit ; l'état
   pilote `data-paused` de l'anneau CSS (P3).
3. **Glisser** limité à la zone visuelle (pas au texte), seuil de 50 px et vélocité minimale ;
   `touch-action: pan-y` sur le panneau pour laisser le défilement vertical ; ignorer le clic qui
   suit un glissement.
4. **Interruption autorisée** : retirer `disabled` pendant l'animation ; une nouvelle commande
   remplace la transition en cours (framer-motion le gère avec `mode="popLayout"` ou en
   réduisant la durée de sortie).
5. **Hauteur** : empiler tous les panneaux dans la même cellule de grille (`grid-area: 1/1`),
   inactifs en `visibility: hidden` + `inert` : la hauteur s'adapte au panneau le plus haut sans
   valeur fixe (et les liens existent dans le HTML, S1).
6. **ARIA** : schéma « carousel » de l'APG — `aria-roledescription="carrousel"` sur la section,
   `role="group"` + `aria-roledescription="diapositive"` + `aria-label="2 sur 4"` sur chaque
   panneau, onglets reliés par `aria-controls`, région `aria-live="polite"` active seulement
   quand l'autoplay est en pause.
7. Alternative à étudier si le carrousel reste coûteux : une rangée `scroll-snap` horizontale
   des quatre projets phares (pas d'autoplay, lien direct, défilement natif).

**Critères d'acceptation**

- [ ] Le carrousel peut être mis en pause à la souris, au clavier et au toucher ; l'état est
      annoncé par les lecteurs d'écran.
- [ ] Sur mobile, un défilement vertical commencé sur le carrousel fait défiler la page.
- [ ] Deux clics rapides sur « suivant » avancent de deux diapositives.
- [ ] Aucune valeur `min-h-[…rem]` dans le composant.
